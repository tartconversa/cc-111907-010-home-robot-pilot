# 家庭服务机器人试点：任务承诺与安全复查

本地运行的运营决策应用。它回答两类问题：

- **对家庭**：哪些请求已经被承接（设备与保障窗口已经占用），哪些还在等确认。
- **对运营**：哪些安排需要人工补充、哪些证据范围太薄、哪些服务应暂停并重新安排。

应用只使用 `inputs/` 中的合成资料与本地工作目录中的状态，**不连接真实机器人、不下发
物理动作**。所有计算在本地完成，Python 标准库，无第三方依赖。

## 快速开始

需要 Python 3.14（与 `pyproject.toml` 一致）。

```bash
# 1. 初始化工作目录（只读来源资料 -> work/state.db）
python -m service_pilot -w work init --now 2026-11-19T08:00:00Z

# 2. 运营查看总览：承接、保障负荷、证据薄弱范围、履约结果
python -m service_pilot -w work ops overview --now 2026-11-19T08:05:00Z

# 3. 评估 Q1：机器人主办 / 人工直接办理 / 暂缓（评估不占用资源）
python -m service_pilot -w work ops assess Q1 --now 2026-11-19T08:05:00Z --all

# 4. 承接 Q1 的机器人主办，指定 S1 接管保障
python -m service_pilot -w work ops accept Q1 --plan robot \
  --start 2026-11-19T10:00:00Z --staff S1 --actor ops-A --now 2026-11-19T08:10:00Z

# 5. 家庭查看本户状态
python -m service_pilot -w work family view F1 --now 2026-11-19T08:15:00Z

# 6. 家庭也可以提交自己的请求（给出时段、任务与采集范围；提交不是承诺）
python -m service_pilot -w work family submit F1 --task drink \
  --earliest 2026-11-19T11:00:00Z --latest 2026-11-19T12:00:00Z --minutes 30 \
  --object cup --environment clear --collection-scope service-only \
  --now 2026-11-19T08:16:00Z
```

`--now` 是演练时钟。省略时使用系统时间；设置后同一工作目录的时钟只能前进，不能倒退。
写操作不能回填到已推进时点之前；历史回看请用 `ops replay`。每次命令都会打开并保存同一个
`state.db`，可随时中断、继续。

## 它如何判断“可承诺”

### 0. 家庭提交请求

`family submit` 只接受家庭允许的任务、与可接受小时有交集的时段，并记录家庭声明的
采集范围。它产生“已收到”状态，不会自动产生服务授权、占用设备或成为承诺。运营仍须
用 `ops accept` 承接。

采集范围是请求级声明，记录在请求事件与审计中；它不替代来源 `consent` 表里的服务/分析
授权。分析资格与机器人主办仍以来源授权为准。

### 1. 证据按设备/版本/任务/物品/环境分层

- 尝试、**机器人独立完成**、**人工接管后完成**、**住户拒绝**、**结果未知** 分别统计。
- 拒绝与未知不计入“完成”，也不计算综合成功率。
- 不同设备或能力版本绝不合并。
- 设备停机期间没有尝试，**不会**因此提高可靠性。
- 历史演示若高度集中于某一环境（例如 75% 以上集中在 `clear`），应用会标为
  “选择性演示”，不能直接外推到所有家庭或环境。

### 2. 机器人主办的门槛

对某个家庭/任务/环境/物品，应用检查：

| 条件 | 说明 |
|---|---|
| 设备声明包含任务 | 设备能力是声明，不是证据 |
| 能力复查 | 最近一条复查为 `fail` 时明确不可承接 |
| 分析授权 | 家庭未授权分析时，历史不能用于评估 |
| 环境本地证据 | 请求环境必须至少有 3 次历史尝试，缺少环境不能默认安全 |
| 物品本地证据 | 请求物品至少出现过 |
| 政策最低量 | `min_observations`、`min_reviewed`、`max_unknown_fraction` |
| 人工复查 | `review_required` 为真时，该环境必须有已复核尝试 |
| 接管保障 | 按风险估计保留合格人员的可用时间 |

只满足门槛不代表风险为零。应用始终披露：

- 接管风险的 Beta 后验均值；
- Wilson 95% 上界与风险等级（低/中/高/不确定）；
- 保障系数：低 1.0×、中 1.5×、高 2.0× 服务时长；样本不足或未知时使用**全窗口保障**。

### 3. 人工保障不能被多户共用

被承接的机器人主办会同时占用：

- 设备在服务时段的时间；
- 一名具体工作人员在**保障窗口**的时间（不是平均概率分摊）。

同一名人员在同一时段只能属于一个请求。第二位运营尝试确认重叠安排时，应用会在事务内
重新核对资源并拒绝，而不是让两家都看到“已承接”。

### 4. 什么算承诺

| 动作 | 是否承诺 | 是否占用资源 |
|---|---|---|
| 评估 / 建议 / 暂缓 | 否 | 否 |
| 替代安排等待家庭确认 | 否 | 否 |
| 已承接 | 是 | 是 |
| 家庭取消（服务尚未开始） | 释放 | 释放 |
| 服务已开始 | — | 不能取消或改派；用 `ops fulfil` 记录实际结果 |

## 常见运营流程

### 维护延期影响已承接服务

```bash
# 导入新的维护记录（received = 运营获知时点）
python -m service_pilot -w work ops import docs/examples/maintenance_extension.json --now 2026-11-19T09:05:00Z

# 找出受影响且尚未开始的服务，查看改期/转人工/取消选择
python -m service_pilot -w work ops incidents --now 2026-11-19T09:10:00Z

# 提出转人工（等待家庭确认，此时不占用 S2）
python -m service_pilot -w work ops propose Q1 --proposal-action human --plan human \
  --start 2026-11-19T10:30:00Z --staff S1 --actor ops-A --now 2026-11-19T09:15:00Z

# 家庭确认后才落位；原安排在替代安排成立后释放
python -m service_pilot -w work ops confirm-proposal 1 --actor family:F1 --now 2026-11-19T09:20:00Z
```

### 已承接后改期或转人工

已承接且**尚未开始**的请求不能再次直接 `accept`，也不会被覆盖。服务一旦开始，应用拒绝
改期、转人工和取消，以保证实际接管与完成事实不被改写。尚未开始的请求必须：

1. `ops propose` 提出替代安排（不占用资源）；
2. 家庭 `ops confirm-proposal`；
3. 替代安排成立后，原设备与保障窗口才释放。

### 家庭撤回任务授权

```bash
# 导入 revoked 授权。已开始的任务保留实际接管与完成事实，
# 但后续新安排与采集遵守撤回后的范围。
python -m service_pilot -w work ops import docs/examples/consent_revoke.json --now 2026-11-19T09:30:00Z
python -m service_pilot -w work ops incidents --now 2026-11-19T09:35:00Z
python -m service_pilot -w work ops assess Q1 --now 2026-11-19T09:35:00Z
```

撤回分析授权后，应用不再使用该家庭历史估计；历史事实上仍保留在来源与履约记录中。

### 证据复查与恢复

```bash
# 复查失败：新的机器人主办被阻止
python -m service_pilot -w work ops import docs/examples/capability_fail.json --now 2026-11-19T09:05:00Z

# 复查通过：恢复机器人主办，但不会自动恢复家庭授权
python -m service_pilot -w work ops import docs/examples/capability_pass.json --now 2026-11-19T09:35:00Z
```

### 回溯

```bash
python -m service_pilot -w work ops replay Q1 --as-of 2026-11-19T08:30:00Z
```

只使用 `as-of` 之前已知的事实重建当时的承诺与候选；`later_facts` 单独列出后来才发现
的事实，不会改写当时披露的风险。

## 命令清单

| 命令 | 作用 |
|---|---|
| `init` | 初始化工作目录，校验清单与字段 |
| `ops overview` | 运营总览 |
| `ops readiness` | 列出每个请求可承接的机器人/人工时段数量与原因 |
| `ops requests` | 请求列表 |
| `ops assess Q1` | 评估候选安排，不占用资源 |
| `ops detail Q1` | 请求详情、证据、候选 |
| `ops preview ...` | 提交前试算一个新请求 |
| `ops accept ...` | 承接（`--plan robot|human`，可 `--staff`） |
| `ops acknowledge Q1` | 标记已受理（不是承诺） |
| `ops reject Q1 --reason ...` | 未承接 |
| `ops cancel Q1 --reason ...` | 取消并释放 |
| `ops propose ... --proposal-action human|reschedule` | 提出替代安排，等待家庭确认 |
| `ops confirm-proposal N` / `decline-proposal N` | 家庭确认或拒绝 |
| `ops incidents` | 受维护/复查/授权影响的服务 |
| `ops fulfil Q1 --outcome ...` | 记录履约结果 |
| `ops replay Q1 --as-of ...` | 按当时可知证据回溯 |
| `ops import FILE` | 导入新记录 |
| `ops clock [--set ...]` | 查看或推进演练时钟 |
| `family view F1` | 家庭视图（仅本户） |
| `family submit F1 ...` | 家庭提交请求与采集范围（不是承诺） |
| `family cancel F1 RQ1 --reason ...` | 家庭取消本户请求 |
| `family confirm F1 N` / `decline F1 N` | 家庭确认或拒绝本户替代安排 |
| `explain Q1` | 解释当前为何可/不可承接 |
| `stats` | 按家庭/任务/环境统计与不确定性 |
| `source-issues` | 来源冲突 |

所有命令都支持 `--json`（放在子命令前或后均可），包括写操作与 `init`，便于接入其他
本地工具。

## 隐私与角色

- `family view` 只返回本户请求、本户授权状态、本户已承接安排的接手人。
  不会返回其他家庭、其他工作人员的排班或运营内部备注。
- `ops overview` 面向运营负责人，关联服务覆盖、失约/取消、人工接管负荷与证据薄弱范围。
- 应用不提供账号系统；角色隔离由使用者选择命令入口和本机文件权限保证。

## 测试

```bash
python -m unittest discover -s tests -v
```

- `tests/test_source_contract.py`：来源资料自身完整性（原有测试）。
- `tests/test_pilot.py`：49 项业务行为测试，覆盖统计分层、资格门槛、保障独占、并发确认、
  维护/复查/授权影响、替代安排、回溯、去重与来源冲突、隐私与工作目录隔离。
  另有针对评审发现的回归测试：已开始服务不可改派、替代安排保留版本与风险披露、
  事件级 as-of 状态、家庭视图不泄露运营备注、拒绝释放占用、导入不可回填。

并发确认可以用两个终端同时运行 `ops accept` 验证：只有一个成功，另一个会重新核对
资源并失败，不会让两户同时看到“已承接”。

`docs/examples/` 提供可直接导入的合成变更记录：维护延期、授权撤回、能力复查失败/通过、
人员临时不可用。

## 工作目录

```
work/
  state.db       # SQLite：来源事实（含 known_at）、请求状态、占用、建议、履约、审计
```

`state.db` 使用 WAL 模式，支持两个运营进程同时操作；重叠确认由 SQLite 事务串行化，
后确认者会重新核对资源。旧版本工作目录打开时会自动补齐履约表的设备/版本列。

- 来源文件 `inputs/` 永远只读。
- 不同工作目录互不污染。
- 建议把 `work/` 排除在版本控制之外（已在 `.gitignore` 中忽略 `outputs/`，也可自行忽略 `work/`）。

## 不做什么

- 不连接机器人，不执行或模拟物理动作。
- 不把平均值当作个体保证，不把未知结果当作成功。
- 不用后来的资料改写当时已披露的风险。
- 不替家庭确认改期或转人工。
